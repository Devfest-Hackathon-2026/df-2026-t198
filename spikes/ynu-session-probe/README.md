# YNU LMSを開いたときに、裏で取得できるかを確かめる試作

製品では、本人がLMSを開いたときに、拡張機能が裏で全授業の課題を取りに行く（docs/decisions.md のD7）。その前提を確かめる。

1. **一番大事：** 拡張機能の裏からの取得に、ログインの状態（Cookie）が付くか。付かなければ、この方式は成り立たない
2. LMSのページを開いたことを、拡張機能が拾えるか
3. 参考：ログインはどれくらい持つか。PCのスリープやブラウザの再起動のあとも残るか。15分ごとにも取りに行って記録する

## 分かったこと（2026-11-05 12:35）

- YNU LMSはセッションIDをURLのpathに `;SID=...` の形で持つ（例：`/lms/homeHoml/doIndex;SID=...`）。ログインは学認のIdP（`gakunin-idp.ynu.ac.jp`）を経由する。
- SIDを付けずにホームを取りに行くと、ログインしていなくても、していても `/lms/error/notLogin`（403）に飛ぶ可能性がある。最初の版はログイン画面を開いた時点で測ってしまい、ログイン後を測れていなかった。

## 結果（2026-11-05 12:40、Soraの環境）

| 取り方 | SIDなし | SIDあり |
|---|---|---|
| 拡張機能の裏（worker） | 取れない（403、`/lms/error/notLogin`） | **取れた**（200、249ms） |
| ページの側（page） | 取れない（403） | **取れた**（200、213ms） |

- ログインの状態はCookieではなく、URLのSIDで決まる。SIDを付ければ、拡張機能の裏からでも画面に触らずに取れる。
- 製品では、ログイン後のページをcontent scriptが見つけたら、SIDを裏の処理に渡し、裏から全授業を取りに行く（docs/decisions.md のD8）。

## 使い方

1. Chromeで `chrome://extensions` を開き、デベロッパーモードを有効にして、「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選ぶ（更新したら再読み込み）。
2. いつもどおりYNU LMSにログインする。ログイン後のページ（URLに `;SID=` がある）を開くと、新しいログインとみなして、4通りで1回ずつ取りに行く：裏から（worker）／ページの側から（page）× SIDを付けない／付ける。同じログインの間は繰り返さない。
3. 拡張機能のアイコンを押し、きっかけが `login` の4行を見る。どれが「取れた」かで、製品の取り方を決める。
4. 「今すぐ確認」と15分ごとの取得は、最後に見つけたSIDを付けて裏から取る。SIDを付けた取得を続けたときに、ログインが延び続けるか、ログインしてから何時間で必ず切れるか、スリープのあとに残るかを測る。

保存するのは、時刻、きっかけ、取り方、HTTPの状態、最後に着いたURLのpath（`;SID=` より前だけ）、かかった時間、SIDのハッシュだけ。画面の中身、URLのクエリ、SIDそのものは保存しない。
