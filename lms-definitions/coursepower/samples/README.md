# CoursePowerの読み取り用見本

C02（授業と曜日・時限）、C03（課題の題名・締切・提出の状態）、C07（読み取り定義）の試験と、M1の正解データに使う。HTMLは保存済みの画面から読み取り部分を抜き出し、個別の内容を架空の値に置き換えたもの。製品の画面全体を再現するものではない。

## ファイルと残した構造

各HTMLと同名の `*.expected.json` が1組。表の行数は見出しを除く。

| HTML | 元のページの種類 | 残した部分 |
|---|---|---|
| `home.html` | ホーム | 曜日ごとの `weeklyCourseArea` と24個の授業カード。授業名、教員、時限、学期の枠。元の画面はtableではなくdivの入れ子 |
| `course-top.html` | 授業トップの教材一覧 | 教材の外側の表、折り畳みの行、内側の表とレポート9行。公開終了、公開期限、未提出、未評価の表示 |
| `assignment-list.html` | 同じ授業の課題一覧として保存した教材一覧 | `course-top.html` と同じ内容。独立したレポート専用画面ではない |
| `assignment-detail-open.html` | 未提出の課題詳細 | 題名のパンくず、提出期間と状況の表、本文の枠 |
| `notice-list.html` | お知らせ一覧 | 見出しと2行。1行は保存済み詳細に対応する。全件取得・ページ送りの成功を示す見本ではない |
| `notice-detail.html` | お知らせ詳細 | 属性の表、題名、関連授業、本文内の段落・強調・改行・リンク要素 |

## 消したものと置き換えたもの

- script・style要素、注釈、外部のCSS・画像等の読み込み、フォーム・hidden値、入力・提出欄、利用者表示、メニュー、フッターを除いた。画像要素と、教材一覧から課題以外の行も除いた。
- 授業名・教員名・課題名・通知名・本文は架空の文字列へ置き換えた。同じ元の値にはページをまたいで同じ架空の値を使った。リンク先URLは取り除き、移動用のhrefは `#` にした。
- 授業、教材、通知の識別子は接頭辞と数字の桁数を残して置き換えた。classと構造用id、表の入れ子、列の順番、colspanは残した。行番号や並べ替え番号は画面の構造として残した。
- 日時は架空の日時へ移し、区切り文字・桁数・曜日付きの書式を保った。曜日も新しい日付に合わせた。項目名・状態・曜日・時限などの製品の固定語は残した。
- `formSubmit`、`kyozaiTitleLink`、`clickTitle` のonclick属性は識別子を読むために残した。引数の識別子は架空。関数を定義するスクリプト、送信フォーム、外部通信先は含めず、これらの操作は実行できない。

## 正解JSONの扱い

正解JSONは試験専用で、[観測の案](../../../docs/data-shapes.md)に近い項目名を使う。公開する型やAPIの変更ではない。HTMLに無い取得時刻や提出時刻は作らない。

- ホームの22授業を識別子でまとめ、複数時限の授業は `slots` に列挙する。曜日・時限のない9カードは `slots: []` とする。曜日は月曜1から、時限は1から。
- `contextOnly` の項目は、そのHTML単独からは読めない。詳細へ進む直前の授業、教材、通知の識別子を試験の入力に渡す。
- 教材一覧の「公開期限」を「提出締切」と決めつけない。一覧の `dueText` と `dueAt` は `null` とし、表示は `availabilityText` に記す。詳細の締切文字は「まで」も含めて `dueText`、変換後は `dueAt` にJSTのオフセット付きで記す。
- 一覧の「未評価」は、材料の採取記録で提出済みと確認された行に対応するため `submitted` とした。表示そのものは `statusText` に保持する。未提出の行は `not-submitted`。提出済み詳細の見本があるという意味ではない。
- お知らせの `bodyText` は本文の空白を整理し、非空のテキスト片を改行でつないだ値。元のHTMLの改行・強調等の要素は別に残してある。本文の内容自体は架空であり、締切変更の意味を判定する正解ではない。
- M1では題名・締切・提出の状態を項目単位で比較する。同一の教材一覧2ファイルを二重に数えない。未測定のM1や読み取り部品の完成を、この見本の検査だけで主張しない。

## 無い見本

- 提出済みの課題詳細。保存した一覧には該当行があるが、公開終了で通常の詳細リンクを開けなかった。
- 全授業を横断した課題一覧、独立したレポート専用一覧。
- 空の授業一覧・空の教材一覧、ログイン切れ・エラー、ページ送りの前後。
- 締切なし・日付だけの締切・読み取り不能な締切の課題詳細、訂正提出・取消など、今回の材料に含まれない状態。

これらの状態を追加するときは新しい材料を取得する。既存見本から状態を改変して、実際に存在した画面として扱わない。

## 点検

repoのルートで実行する。

```sh
pnpm check:samples
node scripts/check-samples.mjs --self-test
```

HTML、正解JSON、このREADMEを検査する。通常の検査は認証用の識別子の表記、メール形式、非公開の原本置き場への参照を拒否する。HTMLのスクリプト要素や外部読み込み属性も拒否する。

原本フォルダが手元にある場合は、全原本HTMLのテキストと属性、4桁以上の数字、除外語の一覧を照合する。文字参照・URL符号化・JSONのUnicode表記・全角文字も正規化する。製品の固定語と構造属性は、[検査スクリプト](../../../scripts/check-samples.mjs)の明示した許可一覧で除外する。原本フォルダがあるのに原本HTMLや除外語の一覧が欠ける場合は失敗する。

検出結果は見本側のパスと行番号に限る。原本の語句・名前は出力しない。CIでは原本がないため共通の検査だけを行い、手元の照合の省略を明記する。自己試験は一時ディレクトリの架空データで検出と非表示を確かめる。

機械検査だけでは、残した範囲の適切さや未知の個人情報までは保証できない。commit前に、固定語の許可一覧・HTMLの内容・正解との対応をレビューする。
