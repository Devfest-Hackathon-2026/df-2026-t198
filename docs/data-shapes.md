# データの形（状態：案、2026-11-05）

取得部品とサーバーの境界。ここを2人で合意すれば、YNUの部品（Sora）と京大の部品（orange）を別々に作れる。変えるときは2人で合意し、`decisions.md` に理由を書く。この雛形のTypeScriptの型は [`packages/core/src/types.ts`](../packages/core/src/types.ts) に置く。

## 観測（取得部品 → サーバー）

取得部品が1回取りに行くたびに、1つ送る。部品は新規・変更の判断をしない。

| 項目 | 内容 |
|---|---|
| `system` | 授業支援システムの名前。`ynu-lms`、`panda` |
| `fetchedAt` | 取得した時刻（ISO 8601、タイムゾーン付き） |
| `courses` | 今回、課題の一覧を最後まで取れた授業。`courseId`、`name`、`slots`（曜日と時限の組。時間割に使う。取れなければ空）。ここに入った授業で課題が消えていれば、取消の候補になる。入っていない授業の課題は「分からない」のまま扱う |
| `assignments` | 課題。下の表 |
| `failures` | 取れなかったもの。`courseId`（全体なら空）、`kind`（`not-logged-in`、`http`、`parse`）、`detail`（SIDや個人の情報を含めない） |

課題の項目：

| 項目 | 内容 |
|---|---|
| `sourceId` | システムの中での課題のID。同じ課題かどうかはこれで決める |
| `courseId` | どの授業の課題か |
| `title` | 題名 |
| `url` | 課題のページ。SIDなどセッションの情報を除く |
| `dueAt` | 締切（ISO 8601）。読み取れなければ `null` |
| `dueText` | 画面に書いてあった締切の文字そのまま。`dueAt` の根拠 |
| `submission` | `submitted`、`not-submitted`、`unknown` |
| `submittedAt` | 分かれば提出の時刻 |

## 台帳（サーバーの中）

| 項目 | 内容 |
|---|---|
| 課題のキー | `system` と `sourceId` の組 |
| 公式の締切 | 最後に観測した `dueAt` と、その根拠 |
| 準備の目安 | 公式の締切と、支援の設定（何日前か）から決める。公式の締切は書き換えない |
| 状態 | 未提出、提出済み、取消の候補、取消 |
| 履歴 | 新規、締切の変更（前と後）、題名の変更、取消の候補、取消、提出。それぞれ時刻と、どの観測からか |
| 要確認 | 締切が読み取れない、文章（お知らせ・メール）と食い違う、など |
| カレンダーの予定 | 公式の締切と準備の目安の予定ID |

取消は、授業の一覧を最後まで取れたのに課題が2回続けて見当たらないときに決める。1回だけなら「取消の候補」にとどめる。

取得の状態は、学生とシステムの組ごとに、最後に取得できた時刻、最後に試した時刻、最後の失敗の種類を持つ。

## 準備の予定（面談画面で作る）

| 項目 | 内容 |
|---|---|
| 課題のキー | どの課題の準備か |
| 日付と時限 | 時間割の空いたコマ。時限の時刻は大学ごとの設定から決める |
| 決めた日 | 面談の日 |
| カレンダーの予定 | 予定ID |

候補は保存しない。面談で入れると決めたものだけを保存し、学生の時間割とカレンダーに出す。

## TypeScriptでの表し方

- 6つの入口の型は `Observation`、`Assignment`、`FetchFailure`、`LedgerAssignment`、`PreparationPlan`、`FetchState`。公開する型は `packages/core/src/index.ts` にまとめる。
- 時刻はタイムゾーン付きのISO 8601文字列。日付だけの値は `YYYY-MM-DD`。曜日は月曜1〜日曜7、時限は1からの数値。型だけでは文字列の形式や数値の範囲を検査しない。
- 全体の取得失敗は `courseId: null`。まだ試していない・成功していない取得時刻は `null`。提出時刻が不明なら `submittedAt` を省く。
- 台帳の `latest` は最後の観測の課題、`officialDeadline` は締切とその根拠。履歴は `system` と `fetchedAt` で元の観測を指す。取消の判定や準備日の計算はまだ実装しない。
- `stripSessionId` はURLのpathにある `;SID=...` を除く。queryとfragmentの内容は変えない。ほかの種類の秘密情報も除く汎用のURL清掃処理ではない。
