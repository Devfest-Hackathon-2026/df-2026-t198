# 画面の言葉の決まり（状態：案、2026-11-05）

学生の画面、支援担当の面談画面、LMSの隅の知らせ、カレンダーの予定に使う言葉の決まり。3つの試作（`design/prototypes/2026-11-05/`）の文言を見直し、「根拠」のような硬い言葉を利用者に分かる言葉にそろえるために作った。

## 決まり

1. **仕組みの言葉を画面に出さない。** 取得、記載、根拠、履歴、反映、基準のような、システムの側から見た言葉を使わない。その人に見えていること、することの言葉にする。
2. **状態は、変わったときと終わったときだけ書く。** すべての課題に「未提出」を付けない。出したものにだけ印を付ける。
3. **何もないときは何も書かない。** 「特記なし」「要確認 0件」を出さない。
4. **数を数える言葉は、まとめの1行だけに使う。** 例：LMSの隅の知らせ。一覧の中で「1件」を付けない。
5. **責める言い方、急かす言い方をしない。** 「期限切れ」「未達」「着手してください」を使わない。

## 「要確認」の使い方（2026-11-05、Sora）

「要確認」は使ってよい。文で書くときは「確認が必要です」でもよい（Sora）。

- 画面では、短い印「要確認」と、何と何が食い違っているかの1文を並べる。例：「要確認　お知らせでは21日(水)に延びたと書かれています」。印だけを出さない。
- 印の色は、警告の赤ではなく、目に留まるが責めない色にする。赤は、今日やらないと間に合わないものだけに使う（D12）。赤にしたい場合はD12と合わせて決め直す。
- カレンダーの予定名は、頭に「【要確認】」を付ける。両方の日付は説明欄に1行で書く。
- 確かめるものが無いときは、印も件数も出さない（上の3）。

## 準備から提出へ（Issue #141）

- 「次は提出」：準備が終わり、LMSで提出済みとまだ分かっていない課題の段。準備の「終わった」と提出の記録を分ける。
- 「LMSを開く」：メールと準備完了後の画面からLMSを開く。学生・面談画面の「LMSで見る ›」も同じリンク先を使う。
- 「道順」：詳細を直接開けないLMSでは「ホーム › 授業名 › 課題名」と書く。リンク先は定義のホーム。直接開けるLMSでは道順を足さない。
- 提出の確認：「提出済みかどうかは、次にLMSを開いたときに確かめます。提出済みと分かると「次は提出」から消えます。」と案内する。

## 紹介ページ（Issue #182）

- 「体験版を開く」：紹介ページ内の「体験する」へ進む。
- 「自分の大学で使う」：開発版のChrome拡張・Googleログイン・対応するLMSの案内へ進む。
- 「しくみ」：架空のSVGの5枚のカードで、先生の締切変更、学生がLMSを開く、ToDokuへの取り込み、予定の更新、支援担当の更新、翌朝のメールを6段で示す。線が光って届け先へ進み、カメラが追う。表示中は自動再生を繰り返し、マウスやフォーカスでは止めない。「一時停止」、画面外、非表示タブ、動きを減らす設定で止める。説明の読み上げは停止中だけ。前後・左右キー・横スワイプで段を選べる。動きを減らす設定では6段の静止一覧にする（Issue #270）。
- 「締切は、ふだん見る場所にも届きます」：しくみの手前の章。Google カレンダー（本人のカレンダーに ToDoku 専用のカレンダーができ、課題の締切と準備の予定が入る）、スマホのホーム画面（ToDoku を追加して学生画面をすぐ開く。課題の取り込みは PC の Chrome 拡張）、朝のメール（課題がある朝 7:30 にクラウドから本人へ送る）の3つを並べる。しくみの1段は約2.4秒。最後の段はメールが届いたあとカメラを引いて5枚全体を見せ（約4.2秒）、1周は約16秒（Sora、2026-11-10）。
- 「対応しているLMS」：横浜国立大学と京都大学を並べる（Sora、2026-11-10）。
- 「体験版」：紹介ページの主な入口を1つにする。設定のあるビルドでは「学生として試す」で体験用LMSへ入り、設定がないときは「体験用LMSを開く」を出す。審査向けの案内は補助の1行にする（Issue #240）。
- 「審査員の方」：説明資料の体験用アカウントを案内する。共用の組と審査の組を混同しない。
- ヒーローの絵は架空の固定日付。学生の時間割と支援担当の面談の一覧に同じ課題（文章表現・第3回レポート）を枠で示し、点線で結ぶ。朝のメールの札を添える。操作できるボタンとしては読み上げない。1章（概要）の画像は、エミュレーターで撮影した架空の授業の画面。両方の画像で同じ課題の締切変更を枠で示す。
- 「はじめに一度だけ、Chrome 拡張を入れて Google でログインします。」：ヒーローの見出し（LMSを開くことだけ）に添える、初回の設定の一行。
- 「架空の授業と課題で、学生と支援担当の画面を試せます。」：体験版の章の説明。

## 共通部品と待ち時間（Issue #223）

- 共有の説明は「共有を許可した学生の授業と課題を出しています。」。許可は学生単位であり、授業ごとの選択があるようには書かない。
- 処理中の操作は、回転する印と「保存中…」「確認中…」などのラベルで示し、終わるまで再度押せないようにする。
- 3秒と10秒を過ぎたら、処理の内容と待機の状態を1行で示す。進んだ割合や完了時刻は推測しない。動きを減らす設定でも、状態を示す文字は出す。
- 共通部品の提出済みは既定で「出せました」、締切後は「締切を過ぎています」。普段の課題の行には「まだ」を足さない。締切を読めなかった状態と、締切の日付だけが分かる状態を区別する。
- 学生・面談ではLMSと準備の用語説明を繰り返さず、横スクロールは表の端の影で示す。

## 説明資料の審査用リンク（Issue #241）

- リンクで入る処理中は「ログイン中…」。終わるまで前の組の画面やログイン欄を出さない。
- 読めないリンク・ログインの失敗は「リンクでログインできませんでした。説明資料のアカウントで入ってください。」と、空のログイン欄を出す。リンクの中身や技術的なエラーは表示しない。

## 面談の2画面（Issue #252）

- 「① 確かめる」「② 相談する」は画面の切り替え。確認側には「締切N件・変化N件」、相談側には「準備の候補 Nコマ」を添える。候補数は「相談する課題」で現在選んでいる課題の候補と同じ関数で数える（Issue #260）。別の課題の候補は合算しない。学生の予定全体が空いていることは示さない。
- 情報カードは「前回の面談」「次の面談」「情報の取得時点」。未設定は「日時未設定」、取得履歴がないときは「取得記録なし」。日時の操作は「面談日時を変える」。
- 主な一覧は「次の面談までの締切」。対象がなければ「該当する締切なし」、日時がなければ「次の面談日時が未設定です。」。変化欄は「変化なし」「前回の面談日時未設定」で区別する。
- 締切の変化は「締切が変わった」、確認が必要な課題は「要確認」、提出の変化は「出せました」。日付のみの締切には時刻を補わず、締切の現地日付との差で「今日」「あとN日」を添える。

## 学生の時間割と体験の入口（Issue #249）

- 時間割の授業名は2行まで。全文はtitleと読み上げ名に残す。締切は「11/10 · 2件」「11/10 17:30 · 2件」のように1行にまとめ、日付だけの締切に時刻を補わない。課題名と詳しい状態は授業を押した先で読む。
- 学生画面の面談の入口は、共有中の学生・体験学生と支援担当に出す。共有がない一般の学生には出さない。
- `/demo-lms` は「学生として試す」「支援担当として試す」を主な入口にする。「審査員の方（説明資料のアカウント）」は閉じた補助の枠にし、リンクでログインできなかった場合は回復用に開く。
- 体験ボタンの設定がない場合だけ「この版では体験版のボタンを出していません。審査員の方は説明資料のアカウントかリンクで入ってください。」を出す。

## 学生の共有の操作（Issue #257）

- 欄の名前は「共有している支援担当」。共有先の表示名を出し、名前を確認できない場合は「支援担当」とし、内部の識別子は出さない。共有先がない学生と共用の体験には欄を出さない。
- 「共有をやめる」の確認は「共有をやめますか？」「この支援担当はあなたの時間割・課題・準備の予定を見られなくなります。」。操作を中止した場合は許可を変えない。
- 停止後は「共有を停止中」と「もう一度共有する」。完了は「共有をやめました。」「共有を再開しました。」。通信や保存に失敗したら完了を知らせず、「共有を変更できませんでした。接続を確かめて、もう一度お試しください。」とする。
- 共有先の新規追加や、すでに相手に渡した情報の回収ができるとは案内しない。取消の時期を無条件に保証する言い回しは使わない。

## スマホの締切とメールの入口（Issue #261）

- 面談の狭い表では、科目・課題の下に「締切」「状況」「残り」を並べる。学生の「今週の締切」は左から日付・授業名と課題名を読む。
- 体験の手順4の「朝のメールを見る」は見本の準備を用意して本文を直接開く。処理中は「開いています…」。受信箱への戻り方と「終わった」「後回し」の確認は同じ。

## 準備の予定を断る理由（Issue #260）

学生の準備、手入力の時刻、面談の「相談する」では、サーバーが断った理由を共通の文で示す。保存に成功した案内は出さず、入力を残す。

| コード | 表示する文 |
|---|---|
| `plan-class-conflict` | その時間にはすでに授業が入っています。別のコマを選んでください。 |
| `plan-overlap` | その時間にはすでに別の準備の予定が入っています。別の時間を選んでください。 |
| `plan-in-past` | その時間はもう過ぎています。これからの時間を選んでください。 |
| `plan-assignment-unavailable` | この課題は提出済み、取り消し済み、または課題の一覧にないため、予定を入れられません。 |
| `plan-after-deadline` | 締切より後の予定は入れられません。締切までの日時を選んでください。 |
| `plan-conflict` | 予定が変わりました。学生の画面で確かめてください。 |

メールの「後回し」と見本作成でも理由を表示する。予定の現在の記録が返った場合は従来どおり現在の状態を示す。見本の締切後は既存の「今日の空いたコマは課題の締切より後になるため、見本を用意できませんでした。締切を確かめてください。」を保つ。未知の409は従来の予定変更の案内を使う。通信失敗では接続や共有の許可を確かめる既存の案内を使い、技術的なエラーやサーバーの本文は表示しない。

## 本人のメール通知（Issue #274）

- 「通知を有効にする」で本人の通知を開始し、「通知を停止する」で止める。送信元の準備や本人アドレスの確認ができないときは、理由を表示する。移行前であることだけでは操作を止めない。
- 初めて切り替えた後は「通知を有効にしました。朝のまとめは次の07:30から、今日やることがある日に送ります。切り替え前に通知の時刻を過ぎた分は送りません。」と表示する。朝より前に有効にした場合も当日の次の07:30を指せるよう、「明日」とは固定しない。対象が無い日の送信や受信箱への到着は保証しない。切替済みの人の再開では「通知を有効にしました。」と表示し、改めて翌朝からになるとは案内しない。
- 停止後は「通知を停止しました。拡張機能からも送りません。」と表示する。すでに送信中のメールを回収できるという意味にはしない。
- クラウド管理中の拡張では「メール通知は学生画面で設定します。この拡張機能からは送りません。」と表示する。学生画面で停止中なら、拡張のチェックを入れても送信を再開しない。

## カレンダーとメールの入口（Issue #278）

- 学生画面の時間割の上に「Google カレンダーに予定を入れる」「朝のメールを受け取る」を並べる。片方だけでも設定できる。設定後は同じ場所に、ボタンの代わりに状態を出す。
- カレンダーの状態は「連携済み」「同期待ち」「再接続が必要」「入れられませんでした」。「同期待ち」「連携済み」はSoraの依頼の言葉を使う。本人の操作が要るときだけボタンを添える（「Google カレンダーにつなぎ直す」「もう一度試す」）。
- 拡張機能が応答しない環境（スマホ、ほかのブラウザ、未導入）では、カレンダーのボタンを出さず「PCのChromeにToDokuの拡張機能を入れて、この画面を開くと設定できます。」と書く。拡張が別のアカウントで使われているときは「拡張機能は別のGoogleアカウントで使われています。この画面と同じアカウントのChromeで開いてください。」。
- 許可が終わらなかったときは「Googleの許可が終わりませんでした。もう一度ボタンを押すと、やり直せます。」。本人を責める言い方（拒否しました、失敗しました）にしない。
- メールは、設定が有効で、送信元と本人のアドレスが使え、前の送信が失敗していない間だけ「受け取り中」と「課題がある朝は、メールが届きます。」を出す（文はSoraが決めた短い言い方）。設定が有効でも送信元や本人のアドレスが使えないときは「準備中」と理由、前の送信が失敗したときは「送れませんでした」を出す。有効にできないときも「準備中」と理由を出す。止める操作は下の「メール通知の設定」に残す。
- 体験版では「体験版では、実際のGoogle カレンダーとメールにはつなぎません。」だけを出し、ボタンは出さない。

## 学生画面と面談画面の読みやすさ（Issue #272）

- 学生の時間割のマスの締切は日付だけ（例「11/12 · 1件」）。時刻は、マスの読み上げ・授業を選んだ先・「今週の締切」に出す。
- 学生の「今週の締切」と授業の課題にも、締切が変わったときは面談と同じ「締切が変わった」の札を付ける。
- 今週の締切が無いときは「今週の締切はありません」。課題が1件も無いときの「まだ課題がありません。…」は変えない。
- 準備の操作は「終わった」を主ボタン、「後回し」を普通のボタン、「外す」を下線の文字にする。
- 面談「相談する」の保存済みの準備は黄色の塗り、候補は点線のまま。保存後の「準備の予定を入れました。」は入れたマスの中に出す。入れたマスが表示中の週に無いときは表の下に出す。


## 体験版の画面の切り替え（FLOW1）

- 「自動で切り替える」は画面の表示だけを切り替える。動きを減らす設定では切り替えず、「学生の画面を見る」「支援担当の画面を見る」で選べる。タブを押すとその回の自動切り替えを止める。
- LMSの変更後：「LMSの締切が変わりました。学生と支援担当の画面は、次の読み取りまで前のままです」
- 読み取り・反映後：「読み取りました。学生の画面です」
- 支援担当へ切り替えた後：「支援担当の画面にも、同じ変更が出ています」
- 「3つ並べて見る」と「1画面ずつ見る」で表示を変える。幅760px以下ではタブで1画面ずつ見る。
