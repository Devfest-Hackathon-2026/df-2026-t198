# 実LMSの属性名と本体フォームの読み取り

ホームのHTTP応答にある属性名は `onClick` で、導入済LinkeDOMは元の大小文字を保持していた。既存の `getAttribute('onclick')` は値を取れず、一覧全体が `unreadable-page` になった。属性名だけをそろえる確認で、同じ応答から22授業を読めた。実ページの本文や値はこの変更に含めない。

同じフォーム名もホームに3個、教材画面に4個あった。本体の一意IDはホームが `homeHomlForm`、教材が `main_form`。既存のID指定を使い、複数フォームなら失敗する境界は保った。

## 変更と判断

- 切り離したツリーのHTML namespaceだけで、属性名をASCII小文字へそろえる。属性値やJS本文を変更せず、実行しない。SVGの既存の扱いは変えない。
- HTMLの読み取りとフォームの読み取りを同じ入口へ接続した。ローカルのライブラリ型宣言は導入済DOMメソッドを補完しただけで、公開データ型・API・依存は変えていない。
- ナビゲーション定義ではフォーム名を本体の一意IDへ変更した。通信先・メソッド・許可フィールドは変えていない。既存の見本と期待値は変更していない。

LinkeDOMの[公式parse処理](https://github.com/WebReflection/linkedom/blob/main/esm/shared/parse-from-string.js)でも `lowerCaseAttributeNames: false` が固定され、公開のparseHTML引数で切り替えられなかったため、既存OSSを使い続けて読取入口だけを補った。依存やライブラリ内部は変更していない。

## 検証

架空HTMLの属性ケース試験は修正前6失敗・1成功から、修正後7成功。worker束の混在ケースも失敗から成功した。フォーム名が重複する架空応答では修正前に授業ごとの取得へ進めず、ID指定後は22授業・132課題の架空観測を作れた。ここでの課題数は架空の試験値であり、実課題数ではない。

属性名・フォーム・空値の修正版（`d159778`）の `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm progress --check`、`pnpm check:samples` はすべて終了コード0。core137件・extension108件・server117件・web35件が成功。通常実行のエミュレーター専用28件はskip。別のFirestore規則38件とHosting検査8件も成功。見本17ファイルは成功し、手元の原本との比較は省略した。

別系統のClaude Codeの見直しでも、今回の読取差分に取り込みを止める指摘はなかった。SVGの扱いには既存ライブラリとブラウザの差が残るが、今回のLMS定義では使っていないため残件とした。

## 詳細フォームの空値

通常の画面操作による詳細POSTでも、`jyugyoHiddenId` は存在するが空文字だった。取得要求の検査も、値の真偽ではなく自身の文字列プロパティの存在で判定する。欠落、継承だけの項目、非文字列、長さ超過は拒否する。許可する通信先・メソッド・フィールド・ID形式・SID照合は変更していない。架空データの回帰試験では空値を含む固定5項目の送信と、境界外の要求を送信前に拒否することを確かめた。

この通常操作ではLMS側のエラー画面への遷移も観測したため、空値の許可だけで実機の詳細取得が成功したとは扱わない。

## 24:00の締切

実機の抽出結果では、既存の許可書式に一致していても時刻が24:00のために締切未読となる例を確認した。元の日付の妥当性を検証した後、24:00だけを翌日の00:00へ変換し、呼出元のUTC offsetを保つ。24:01、25:00や不正な日付は受け入れない。提出期間の本文が `-` の別ケースは意味を解釈せず、処理も変更していない。

架空の日付による回帰試験で、同月・月末・年末・閏年・世紀年の境界とoffset保持を確認した。変更前はfocused試験で12失敗・44成功、変更後は56成功。既存単体試験の24:00を不正とした例は24:01へ置き換え、保存見本・期待値ファイル・採点方法は変更していない。最終のcore158件とextension108件、両パッケージの型・lint・buildは終了コード0。この試験の成功だけでは、実機の未読が解消したとは扱わない。

全体の型・lintも成功。全体testの再実行は、他の作業が使うHostingの5002番との競合で停止した。相手のプロセスを止めず、パッケージ単位の全試験・build・進捗整合・見本点検を別途実行した。全体の再確認はPRのCIでも行う。
