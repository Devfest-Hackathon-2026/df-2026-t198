# Issue #178 共用の解析枠の修正（2026-11-08、PR #181）

Soraの追加決定に合わせ、共用の回数制限を取り除き、通常の解析と別の事故止めの枠で予約・精算する。対象はPR #181の追加修正。初回の入口・準備処理の記録は [初回検証](2026-11-08-issue-178.md) に残す。現在の契約は [data-shapes.md](../data-shapes.md#お知らせの受信と要確認issue-45)、決定は [D38](../decisions.md#d38-紹介ページから入れる共用の体験の組を足す2026-11-08issue-178)。

## 確認した条件

- サーバー保存のプロフィールが `public: true` の解析は `publicAnnouncementUsage/{日本時間の日付}`（3,000円）、それ以外は `announcementUsage/{日本時間の日付}`（10,000円）を使う。送信前の予約とusageによる精算を同じ共通部品で行い、失敗・usage不明では予約を残す。どちらも暴走などを止める事故止めで、ローカルM3評価の予算は変更していない。
- 共用で12回の解析に成功し、通常枠は変化しない。同じ版の再送・不正入力では予約しない。共用の同時予約は残額に収まる1件だけ成功し、満杯では429と固定コード `public-demo-limit`、no-storeを返す。延長・やり直しは使え、やり直しても消費は戻らない。
- 共用枠の残額不足でも審査用と同じ非共用プロフィールの解析は成功し、逆に通常枠が満杯でも共用の解析は成功する。両方の上限ちょうどまでは予約でき、超える予約は拒否する。
- 日本時間の23:59:59から翌日0:00:00で両枠とも再開し、前日の金額と回数は維持する。共用の予約拒否ではモデルを呼んでいないため受領記録を取り消し、同じお知らせを翌日読み直せる。実際に呼んだ後の失敗は受領記録と予約を残し、再試行しない。
- 利用者から送られた `public` は拒否し、プロフィールを確認したサーバーだけが枠を選ぶ。クライアントのFirestore規則・認証方式・依存・クラウド設定は変更していない。
