# Issue #49：準備予定の保存と取消（2026-11-06）

## 対象と合意

対象は学生と共有中の支援担当。面談の候補を選んで時刻を指定し「入れる」と保存できる。学生は自分の画面でも追加でき、支援担当が入れた予定も外せる。登録者を表示し、双方が面談日時を保存できる。[案A](https://github.com/shieikan/kadai-hisho/issues/49#issuecomment-6675841950)・[人の印](https://github.com/shieikan/kadai-hisho/issues/49#issuecomment-6675842677)の範囲。orangeの合意を記録するまでmergeしない。

作業開始時のbranchは `issue-49`、未コミット変更はなかった。新しい依存、Firestore規則、クラウド資源は追加していない。実物のLMSの見本・課題・認証情報は使わず、試験は架空データだけで行った。

## 実装前の計画と確認方法

- coreの予定の型と既存のカレンダーの版管理を広げ、serverの保存APIで許可・課題・空きコマを確認する。予定と同期対象を同時に保存する。
- webの面談候補と学生画面に追加・取消・登録者の表示をつなぐ。候補を見ただけでは保存しない。時限の時刻設定がないため、保存する人が日本時間で開始・終了を入力する。
- 他人・共有取消後の要求、同じIDの再送、取消後の遅れた保存、体験用と実物の分離を試験する。実ブラウザ2文脈で保存・画面・模擬カレンダーを照合する。
- 対象外の取得部品、依存、クラウド操作が必要になった場合は止める。実物のGoogleカレンダーへの書き込み成功はこの試験から主張しない。

先に合格する操作を試験にし、変更前のHTTPルーティングと面談日時の権限に対して実行した結果は5件失敗。準備予定の要求が404、学生本人の面談日時保存が403だった。その後の実装で同じ5件が成功し、入力・同時再送・模擬同期失敗・体験データ分離の試験を追加して8件成功した。

## 判断と残る確認

C24・C25をIssue #49の合格範囲で満たし、PLAN.mdを全体26/41・必須25/37に更新した。現行契約は [data-shapes.md](../data-shapes.md#準備予定の保存と取消issue-49)、判断は [D25](../decisions.md#d25-学生と支援担当が準備の予定を入れ学生が外せるようにする2026-11-06issue-49) を参照。

- 時限と実際の時計の対応を推測しないため、時刻は利用者が入力する。指定時限に授業がないことはAPIで確認するが、入力時刻が大学の時限と一致するか、個人の予定や他の準備予定と重なるかは検査しない。
- 実物用の同期対象と、偽のGoogle APIへの準備予定の作成・取消・応答喪失後の再試行は確認済み。実物のGoogleへの書き込みは未確認で、C15の実機確認に残る。拡張機能には定期同期を追加していないので、起動・観測送信後など既存のきっかけまで更新待ちになる。
- デプロイと公開先での操作確認は行っていない。orangeの設計合意とClaudeの見直しを経て取り込む。
- 認証済みUID、共有の許可、APIの入力、体験データの分離、取消と再送を検査した。ログイン方式・秘密の管理・依存・課金・デプロイ設定は変更対象外。大量アクセスや大量データの評価は行っていない。

この作業者によるソースと画面の見直しは、別系統の独立レビューには数えない。
