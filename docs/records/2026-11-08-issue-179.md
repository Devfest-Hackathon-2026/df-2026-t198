# Issue #179：KULMSの取得と読み取り

2026-11-08、架空のJSONとローカルのエミュレーターで確認。実物のKULMSには接続していない。実装の契約は [data-shapes.md](../data-shapes.md#kulmsのjson読み取りissue-179)、判断は [D38](../decisions.md#d38-kulmsをjsonの専用定義とページ側の取得でつなぐ2026-11-08issue-179)。

## 実装した範囲

- KULMSのページを開いて2秒操作しないと取得を始める。content scriptが同一originの`/direct`へGETし、授業一覧は空の終端ページまで読む。授業別の課題custom actionは全件応答として読み、Cookie・利用者ID・生のJSONをworkerに渡さない。
- workerは既存のFirebase認証、観測API、取得状態の表示とカレンダー同期を使う。同じ接続先では一度に1回だけ取得し、成功後10分は待つ。失敗後は開き直して再試行できる。通信失敗のGETは1回、観測POSTは同じID・本文で1回だけ再試行する。
- 操作中は学生の操作を止めず、取得を中断する。ページ移動・非表示でも中断し、同じページでの操作後は2秒後に再開を求める。YNUの取得コード・定義・ナビゲーション制御には変更なし。
- `panda`を`kulms`へ置換し、`kulasis`を型・入力検査・表示名に足した。KULASISの取得と統合は#180。LMSのお知らせは今回有効化していない。

## 学期・終了・提出の判定

- **今の学期は未判定**。調査文書に学期を確定する項目がないため、`currentTerm`は省略する。D28の「未知の学期は取りこぼしを避けて取得する」に従い、授業名や作成日から推測しない。学期への限定は達成していない。代案はorangeが実物で学期を示す項目を確認し、#180の明示的な授業対応から学期を補うこと。
- `dueTime.epochSecond`（秒）と`nano`を読む。カレンダーのミリ秒や`closeTime`は使わない。締切が観測時刻より前なら終了IDだけを送る。等しい場合は残す。欠損・null・不正値は締切不明とする。
- 現在の利用者IDと`submitters[].id`の一致を確かめ、該当する唯一の提出記録のboolean `submitted`を読む。自分の提出と確認できない・記録がない・値が欠ける・矛盾する場合は`unknown`。点数や添付の有無で未提出と判断しない。取得の前後でLMSの利用者が変わったら観測を送らない。
- `slots: []`は既存の「曜日・時限のない授業」に出る。授業ボタンから課題とLMSリンクを開ける。KULMS/KULASISの時間割が未確認の間は空きコマ候補を出さず、空配列を空き時間の根拠にしない。
- HTTP 401、認証へのredirect、HTMLのログイン画面、現在の利用者IDの欠損は`not-logged-in`の失敗。403/500をログイン切れと同一視しない。失敗した一覧は`listComplete: false`で、空の完全な一覧として送らない。

## orangeの確認手順（#152 C1・C2に追加）

前提：このPRと必要な#180がmainに入り、担当者が通常の接続設定でビルドした拡張を読み込み、学生画面と同じGoogleアカウントで連携済み。PRの単体確認はKULASISなしでも行え、その場合は「曜日・時限のない授業」を見る。

1. **C1に追加**：KULMSへ通常の方法でログインし、トップのタブで2秒操作を止める。拡張の「課題を更新しました」と、学生画面のKULMS取得状態を確認する。全授業の件数・読めた件数・失敗の有無だけを記録する。授業一覧の終端まで取得できたかも確かめる。
2. 学生画面の「曜日・時限のない授業」を押し、課題名・締切・提出の状態をKULMSの画面と目視で照合する。未提出・下書き・提出済み・記録なし・締切不明・締切を過ぎた課題を可能な範囲で選ぶ。記録は対象件数と一致件数だけ。不明が多い場合は`submitters[].id`を実物で確認できるかを調べ、実値をIssueに貼らない。
3. 日時を日本時間で照合し、秒とミリ秒を取り違えていないかを確かめる。締切を過ぎた既存課題は終了欄に残り、新たな終了課題は台帳へ追加されないことを確認する。
4. 学期を示す項目があるかを確認する。現状は学期不明のため過去のサイトも取得対象になり得る。今学期だけ取れたとは記録しない。#180で明示的な対応付けが済むまでは、曜日・時限や空きコマの正しさも完了にしない。
5. 読取中にリンク・キー・フォームを操作し、その操作が止まらず、中断後に2秒静置すると再試行されるかを確かめる。YNUも使う環境ならYNUの取得が従来どおり動くかを確認する。成功後の開き直しは10分の待ちがある。
6. **C2に追加**：成功後10分以上待ってからKULMSだけログアウトし、ページを開く。拡張に「LMSを開き直してください」が出て、学生画面のKULMSの最終試行が失敗になり、既存の課題が消えたり取消にならないことを確認する。待ち時間を避ける場合は拡張を再読み込みしてからログアウト状態のページを開く。
7. 通常の方法で再ログインし、開き直して回復するかを確認する。結果は#179へ件数・一致件数・失敗コードのみでコメントする。生JSON・課題名・個人ID・認証画面のURL・Cookieを貼らない。セッション保持は時間を置いた回を別に記録する。
