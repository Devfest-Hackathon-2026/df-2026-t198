# Issue #232：スマホのホーム画面からの起動

対象は `issue-232-pwa`、開始点はmain `37b503d`。検証した実装は `b2c74e9`。依存を追加せず、manifest・既存ロゴのPNG・service workerを足した。学生画面・認証方式・API・データ契約は変更していない。

## 実装と公式の根拠

- 色の正本は `packages/web/src/shared/styles/tokens.css` の `.app`。`--ink: #18202e` をtheme-color、`--paper: #f7f8f4` をbackground-colorに使う。試験で値の一致を確かめる。
- iOS向けの表示指定はmanifestの `display: standalone` とapple-touch-iconを使う。[WebKitの公式資料](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)はこのmanifestによる起動とapple-touch-iconの優先を説明している。旧来の専用metaは追加していない。[iOS 26](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/#every-site-can-be-a-web-app-on-ios-and-ipados)では追加時の「Webアプリとして開く」を有効にする。
- [Chromeの公式資料](https://developer.chrome.com/blog/update-install-criteria)では、メニューからのインストールにfetch handlerを求める条件はAndroid版108・デスクトップ版112から撤廃されている。今回はオフラインで殻を返す要件のために実装した。空のfetch handlerは使わない。
- [Lighthouseの公式資料](https://developer.chrome.com/docs/lighthouse/pwa/installable-manifest)はPWA監査の廃止を案内している。手元のLighthouse CLIは無いため、ChromiumのDevTools Protocolによるmanifest解析と `Page.getInstallabilityErrors`、実際のキャッシュ・オフライン・版の交代で確かめた。localhostは安全なコンテキストとして試験し、実配信では既存のFirebase HostingのHTTPSを使う。
- `/api`・`/__` 以下、別origin、GET以外には `respondWith` を呼ばない。保存するのは静的なindex.htmlと同じoriginのハッシュ付きJS・CSSだけ。ナビゲーションはネットワーク優先で、通信失敗時だけ殻を返す。認証情報や台帳はservice workerに保存しない。
- ビルド内容からキャッシュの版を自動で変える。新しいworkerは `skipWaiting`、旧版のToDokuキャッシュの削除、`clients.claim` を行う。他のアプリのキャッシュは消さない。ハッシュ付き静的ファイルの照合だけ `ignoreVary` を指定し、配信の `Vary: Origin` によるオフラインの読み落としを避ける。
- アイコンは `favicon.svg` から既存Playwrightで描画した。再生成は `PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node scripts/generate-pwa-icons.mjs`。maskableの印は中央80%の安全な円の中に収めた。外部素材は追加していない。

## Soraの実機確認

1. この変更のデプロイ後、iPhoneのSafariで配信先の `/student` を開き、共有から「ホーム画面に追加」を選ぶ。「Webアプリとして開く」があれば有効にして、ToDokuの印と名前で追加する。
2. Safariを離れ、ホーム画面の印を押す。ブラウザのURL欄が無い独立した画面で学生画面が開くことを確かめる。
3. ホーム画面から開いた状態でGoogleログインを押し、アカウント選択から戻って学生画面の読み込みが完了することを確かめる。特にiPhoneはpopupが開くか、選択後に元のアプリへ戻れるか、戻った後にログイン済みになるかを確認する。閉じて再度開き、同じ本人で表示できることも確認する。
4. AndroidのChromeでも `/student` を開き、メニューからインストールまたはホーム画面への追加を行う。アイコンからの学生画面の起動・Googleログイン・再起動を確かめる。
5. 一度オンラインで開いた後、機内モードで再度開いて画面の殻が出ることを確かめる。課題が最新であることや保存成功は求めない。通信を戻し、開き直して最新状態を取得する。

実機でのホーム画面からの起動とGoogleログインは未確認。失敗時は端末・OS・ブラウザの版と、popupが開かない／戻れない／ログイン状態にならない、のどこで止まるかを記録する。見直しとmerge・デプロイは統合役へ引き継ぐ。
