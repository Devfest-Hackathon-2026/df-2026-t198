# Issue #70：再デプロイ後のHTMLの再検証

## 目的と変更範囲

審査者が再訪したとき、古いHTMLを1時間使い続ける状態を防ぐ。確認者が設定・公開先の応答・残る制約を照合できるように記録する。

作業前にIssue #70、指定文書、Fableの指摘7を確認した。変更予定は `firebase.json` のヘッダー、`scripts/hosting-cache.test.mjs`、ルートの試験コマンド、この記録に限定。HTML5経路と参照JS・CSSのHTTP応答を合格根拠とし、公開先と手元のファイルが異なる場合はデプロイを止める方針で進めた。

- `**/*.html` と `/`、`/student`・`/session`・`/demo-lms` に `Cache-Control: no-cache` を指定。
- Viteのハッシュ付きJS・CSSを置く `/assets/` は `public, max-age=31536000, immutable`。
- [Firebase公式の設定仕様](https://firebase.google.com/docs/hosting/full-config#headers)では書き換え前のURLでヘッダーを照合するため、SPAの入口にも明示した。APIの転送設定は従来どおり。
- `pnpm test:hosting-cache` を通常の `pnpm test` に追加。実際のHostingエミュレーターにHTTPで要求し、HTML5経路・参照するJSとCSSを検査する。`HOSTING_ORIGIN` の指定で同じ試験を公開先にも実行できる。
