# Issue #47 公開先の検証計画

目的は、試す人が公開先で先生役の締切延長から学生・体験用カレンダー・面談の更新まで進めることを確認し、見直し役がC34とC14の証拠を判断できるようにすること。

## 対象と手順

- mainと一致する開始時の版 `bd47aa7` を、`docs/deploy.md` の既存プロジェクト・サービスへ反映する。Cloud Runの専用サービスアカウントを毎回指定する。IAMを変えないため、既存の公開権限を再設定する `--allow-unauthenticated` は付けない。ソースのアップロード一覧を先に確認する。
- Hosting用のFirebase Web設定は公開先の初期設定からメモリで取得してビルドに渡す。ローカルの認証ファイルや設定ファイルを作らず、Hostingのみ反映する。Firestore規則とアカウントは変更しない。
- `packages/web/tests/demo-m6-live.browser.mjs` を追加する。既存のローカルM6と同じ8手順・分母を使う。公開先と明示引数を固定し、許可されたアカウントファイルだけを読む。`trial-1`を使用し、締切延長が残ることを記録する。
- 学生と支援担当を別のChromium文脈でログインさせる。画面の操作で観測を送り、本人のID tokenによるFirestore読み取りで台帳・受領記録・保存済み模擬予定・版を照合する。先生役の操作後、再取得前には台帳とカレンダーが変わらないことも確かめる。
- 実サーバーの応答を受け取った後にブラウザへの応答を落とし、同じ観測IDで再送する。履歴・予定・版が増えないことを確認する。秘密・本文・生例外・trace・HARは保存せず、結果と伏せた画面だけを記録する。

## 変更するファイル

試験の追加、`docs/records/2026-11-06-issue-47-live*` の計画・結果・画像、`docs/demo.md`の公開先手順、`PLAN.md`のC14・C34・M6と集計だけを変更する。製品コード、依存、API、型、試験の正解は変更しない。

## 検証と停止条件

`pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm progress --check && pnpm check:samples`、`pnpm test:demo:emulator`、`pnpm metrics:m6`、公開先の8手順を実行する。ローカルと公開先のM6は別々に記録する。デプロイのbuild ID・revision・URL・日時と、認証済み観測の受領・台帳保存を残す。

権限不足・Cloud Buildの失敗・追加IAMや資源が必要な場合は権限を広げず停止し、Issueに根拠と代案を記す。公開先で失敗した手順と未到達手順も分母に残す。C14・C34のチェックは証拠を得てから更新する。実物のGoogleカレンダー、実LMSのM4・M5・M7、提出用repoは対象外。PR作成後はClaudeの見直しに渡し、mergeしない。
