# READMEだけで公開先を試した結果（C35、2026-11-06）

## 対象と確認方法

Issue #48の受入確認として、READMEの実装を担当したCodexとは別の系統のClaude Codeが、2026-11-06 17:37〜17:40（JST）に[公開先の体験用LMS](https://project-00439085-4e2d-44c3-9a8.web.app/demo-lms)を試した。操作の手掛かりは変更前のREADMEの「ブラウザで試す」だけ。PlaywrightのChromiumで、学生と支援担当を別のブラウザの文脈に分け、Chrome拡張は使わなかった。

元記録はIssue #48で指定された `reviews/c35/report.md`。以下はその要約であり、今回Codexが公開先の操作をやり直した記録ではない。体験用のアカウントは、提出の説明資料の代わりに手元で渡されたものを使用した。アカウントの値はこの記録と画像に含めない。CLAUDE.md経由でAGENTS.mdが自動で読み込まれたが、そこには体験の手順はなく、操作の判断には使わなかったと報告されている。

## 操作結果

開始時は前の試用によって締切が1日延びていた。「体験を最初からやり直す」を押すと初期状態に戻り、この試用では「架空の観察ノート」の締切が11/9 17:00になった。初期日付は固定ではない（`packages/server/src/demo-initial.ts` がリセット時刻から決める）。

| READMEの手順 | 結果 | 観察したこと |
|---|---|---|
| 1 学生でログインし、LMSを開く | 成功 | 課題を確認した旨の案内が出た |
| 2 学生の時間割と締切を見る | 成功 | 別タブの授業の欄・時間割のマス・締切のカレンダーに11/9 17:00が出た |
| 3 別ブラウザの支援担当で面談を開く | 成功 | 担当する学生を選ぶと「次の面談までの締切」に11/9 17:00が出た |
| 4 先生役で締切を1日延ばす | 成功 | LMSだけが11/10 17:00になり、学生・面談画面は11/9のままだった |
| 5 もう一度LMSを開く | 成功 | 再読み込みなしで、学生の授業の欄・マス・カレンダーと面談の締切が11/10に変わった。面談に締切の変更が1行出た |
| 6 さらにLMSを開き、両方でログアウト | 成功 | 対象の予定は1件、締切の変更は1行のまま。面談の変化は全体で3行のままで、再読み込みしても同じ。両者ともログイン画面に戻った |

手順1〜6はすべて成功したため、C35の別系統による試用は合格。これは公開先の体験用カレンダーについての結果であり、実際のGoogleカレンダーの確認ではない。M6の自動測定とは別の受入確認で、M1〜M7の値はこの試用から更新しない。

## READMEに反映した点

1. 公開先でログインできた事実に合わせ、「公開先のアカウントは準備中です」を削除した。アカウントの案内先は提出の説明資料とし、公開先と手元の両方で手順1〜6を使えると書いた。
2. 手順1に「体験を最初からやり直す」を加えた。前の試用の締切を引き継がず、最初の締切を確かめてから始められるようにした。
3. 手順6で見る場所と数を明記した。学生の「締切のカレンダー」の対象予定は1件、面談の「前回の面談からの変化」の締切変更は1行を確かめる。
4. 同じ手順内の言葉も画面に合わせた。学生画面が別タブで開くこと、戻るタブ、先生役のボタンの場所、再読み込みせず変化する欄を具体的に書いた。

## 残る範囲

提出の説明資料へのアカウント記載・配布の完了は、この確認の対象外。試用後に直したREADMEを別系統がもう一度試す確認も行っていない。提出済みの別の課題もカレンダーに出ることが対象と紛らわしい、という画面側の指摘は残る。今回のIssueでは画面を変えず、対象の課題名をREADMEに明記した。
