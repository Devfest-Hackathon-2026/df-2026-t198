# F2 学生一覧の作業計画

Issue #302。大会後向けの draft PR に留める。PLAN.md の条件・チェック、提出物、実行環境は変更しない。

## 既存の部品と限界

- `students/{uid}/supporters/{supporterUid}` は学生ごとの許可。`sessions/store.ts` の `listStudents` は複数学生を返し、`scopes` に `all` があり `revokedAt === null` の対象だけを選ぶ。複数学生への対応に構造変更は不要。
- `/session` は既に担当学生の入口。既存 `SessionServices.students` と `watchSession`、`SessionLink` で集計と面談への移動を実装できる。面談の確認・相談画面は変えない。
- `watchSession` はサーバー由来の許可を確認してから7種類の共有データを読む。停止・失敗時は消去して購読を解除し、遅い通知を無視する。一覧も同じ境界を使い、許可確認中には名前を出さない。
- 通常学生の表示名は共有されていない。担当学生APIの `displayName?` は体験学生の架空の名前に限定される（data-shapes.md、Issue #129）。既存どおり名前がなければ「学生」とIDを表示する。Authの名前・メールから補完しない。
- 通知設定・通知結果・送信記録は共有対象外。一覧には読み込まない。D13の画面部品、D16・D26・D42の共有と取得時点の説明に従う。

## 実装と判定

支援担当が先に確認する学生を選べる一覧にする。`packages/web/src/features/session/student-list.tsx` と `student-summary.ts` を追加し、`page.tsx` の選択部分だけを差し替える。外部に保存する型・API・rules・依存は変更しない。

- 既定は今後の締切が近い順。「変化が多い順」に切替可能。同じ値は学生ID順、締切不明・該当なしは後ろ。
- 締切は未提出・取消/終了以外のLMS課題と有効な手入力課題。今週は日本時間の月曜〜日曜、現在以降。日付だけならその現地日付を含め、表示に時刻を補わない。
- 変化は既存 `lastSessionAt` より後、現在まで。未設定は「前回の面談日時未設定」とし0件と断定しない。閲覧履歴は追加しない。
- 準備は `status: active` の有無。取得時点は成功日時の最新値を示し、取得失敗・古い情報も添える。
- 名前を含む行は共有データがすべて確認できてから表示。共有停止・購読失敗でその行を消す。他の学生は残す。API再取得失敗時は一覧を消し、ログアウト・画面遷移時は購読を解除する。
- `session-page.test.tsx` に一覧の停止・遅い通知・再取得・切替の試験を追加。停止後に名前が残る既存動作をREDとして先に確認する。集計の境界値を `student-summary.test.ts`、複数学生の許可分離を `scripts/firestore-rules.test.mjs` と共有エミュレーター試験で確認。
- 架空データとローカルエミュレーターで1280px/390pxの表示・並べ替え・面談への移動・取消を確認し、画像を確認する。
- 必須検査は `pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm progress --check`。加えて共有エミュレーター試験。前後の試験件数をPRへ記録。M1〜M7の対象範囲を明記し、未測定を推測で埋めない。

## 変更案：通常学生の表示名共有（合意待ち・未実装）

本人が支援担当ごとに共有する名前を入力する案。以下は契約案であり、製品コードから参照しない。

```ts
type SharedDisplayNameInput = { displayName: string | null };
type SharingGrantNameExtension = { displayName?: string };
```

- API案：`PUT /api/v1/sharing/supporters/{supporterUid}/display-name`。tokenの本人の既存許可だけを更新する。trim後1〜80文字、制御文字禁止、`null` は削除、未知のフィールドは拒否。新しい共有許可を作らない。
- Firestore案：既存許可文書に任意の `displayName` を置く。名前更新は共有状態と同じトランザクションで確認。共有停止時は名前を削除し、再開しても自動復元しない。
- rules案：現行の「本人とその支援担当が許可文書をread、client writeは拒否」を維持。新しいread許可は不要。停止した許可文書自体は既存どおり読めるため、名前の削除が必要。
- 担当学生GETの型は維持するが、通常学生にも本人が入力した名前を返す意味変更が必要。停止済み・別の支援担当には返さない。体験学生の既存表示名は維持する。
- 理由：本人が選んだ呼び名だけを、既存の共有先に渡す。採らなかった案はAuthの名前の自動転用（本人の共有意思を確かめられない）、全支援担当共通のプロフィール（共有範囲を広げる）、クライアントの永続キャッシュ（停止後に名前が残る）。
- 合意が要る箇所：入力と停止時削除の仕様、API追加、許可文書の型、通常学生へのGET応答の意味変更。合意後に `docs/decisions.md` と `docs/data-shapes.md` を更新して実装する。今は案と未実装の受入試験だけをbranchへ置く。

## 境界と残る確認

対象資産は共有された名前・課題・予定。攻撃者は別の学生IDを指定できるログイン利用者。APIとFirestore rulesの両方で未共有の学生を拒否すること、取消と遅い通知で表示が復活しないことを確認する。新しい入力・認証・秘密・依存・決済・デプロイは扱わない。通信断中の取消の即時反映、大人数での購読コスト、実アカウントでの確認は未検証。既存APIの全許可文書走査はこの変更では変えない。

権限・保存契約の追加、本番アクセス、別担当の取得部品の変更が必要になったら該当部分を停止する。draftの解除・mergeは行わない。別系統のレビューは未実施としてPRに残す。
