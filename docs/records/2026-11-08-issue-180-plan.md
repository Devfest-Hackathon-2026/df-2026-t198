# Issue #180 実装計画

- 目的：学生・支援担当が、KULASISの時間割のコマで、明示の対応が取れたKULMSの課題を確認できるようにする。実物のDOM・リンク先の形式は未確認。架空見本による合格と、orangeによる実物確認を区別する。
- 取得：`lms-definitions/kulasis/`、`packages/core/src/kulasis-reader.ts`、`packages/extension/src/kulasis-{collection,content,worker}.ts` を追加する。同一originのGET・CP932の復号・表の見出しによる曜日時限の判定。即時のログイン遷移は失敗、遅延ログアウトは追跡しない。取得できない表を空の時間割として送らない。
- 対応表：`Course.kulmsSiteId` をKULASISの授業にだけ持たせる。授業サポート内の科目リンクから、workerが固定したKULMSのURLをGETし、最終URLがsiteIdを表す場合だけ保存。授業名で結び付けない。`types.ts`・サーバーの入力検査・`docs/data-shapes.md` を合わせる。元の授業はsystemごとに別保存し、共通関数で表示用の授業を組み立てる。
- 統合：`packages/core/src/course-links.ts` と学生・面談画面で同じ統合を使う。KULMSの名前・URLと課題キーを維持し、曜日時限はKULASISを使う。課題のカレンダー予定は既存のKULMSキーのまま。時限の実時刻は未確認のため準備予定に別大学の時刻を補わない。
- 100件：`kulms-collection.ts` で既知の授業種別・公開状態だけを判定し、未知の値は除外しない。対応する授業を優先し、未対応は今後の締切がある課題を持つものを残す。100件を超える分は固定の失敗にする。送らない授業の完読結果を作らない。対応の優先用キャッシュは本人・学期を分け、サーバーに保存する対応表と区別する。
- 試験：取消と送信元の境界はRED-firstで、CP932・表の両方向・ログイン切れ・対応の成否・名前だけ一致・属性保持・101件以上を要件から試験化する。既存の正解と判定基準は変更しない。
- 検証：指定6検査、`pnpm metrics:m6`（8/8）、関係するエミュレーター試験と架空データの画面確認。`fixtures-local/` は読まない。`check:samples` がローカル資料を参照し得るため、実行前にスクリプトの挙動を確認し、必要なら資料のない一時コピーで同じコマンドを実行する。
- 完了の根拠：試験結果・差分・CI・head、実物での確認手順を記録し、PLAN.mdに該当条件の証拠を追加する。PRテンプレートの5見出し・Closes #180・著者印を使用する。
