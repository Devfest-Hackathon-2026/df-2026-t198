# Issue #113 の実装計画

対象は本人が希望した場合のGmail通知。PR #79 の上に積み、#112 のdigest応答を使う。変更は `packages/extension/` とこのIssueの新しい記録だけとする。既存のC番号を新たに満たす変更ではないので、PLAN.mdのチェックと数字は変えない。

- `src/digest.ts`：拡張内の応答型、JSTの日付と送信時刻、本人だけの宛先、秘密情報の拒否、UTF-8のメール生成。追加依存なし。
- `src/digest-browser.ts`：既存Firebase認証でのdigest取得、Gmail API、初期OFF・本人ごとの設定、日付と予定IDだけの重複防止、Chrome起動とalarms。毎分確認して追加・移動・取消された準備予定にも追従する。
- `src/service-worker.ts`、`src/options.ts`、`options.html`：設定画面だけからのON/OFFと状態表示。LMSからの設定変更を拒否する。
- `src/oauth-scopes.ts`、`build-config.mjs`、既存の認証2箇所：manifestにgmail.sendを足し、既存の認証は元のscopeを明示してGmailの許可を求めない。
- `tests/digest*.test.*` と既存の関連試験：時刻・起動・重複・OFF・empty、本人の確認、scope、秘密情報、本文の保持を偽APIで検証する。新しい権限境界は先に失敗する試験を実行する。

全体検証は依頼の6検査。設定UIはブラウザで操作し、1280pxと390pxで確認する。Google Cloudの設定、実メール送信、デプロイは行わない。実Gmailの受信はmerge後にSoraが確認する。

Gmailの送信には冪等キーがないため、送信直前に日付と予定IDを保存して同じ通知の再送を防ぐ。応答喪失時は自動再送せず、未着の可能性を記録に残す。APIの失敗や秘密情報の検査失敗では送信しない。課題本文・メール本文・トークンはlocal保存しない。

APIの具体的な項目名は#112の実装・Issueと照合して合わせる。新しいscope・依存・APIの追加や、許可外のファイルの変更が必要になれば停止する。PRには6検査、偽APIの条件、UI確認、実受信の未確認を分けて記載し、Claudeへレビューを引き継ぐ。
