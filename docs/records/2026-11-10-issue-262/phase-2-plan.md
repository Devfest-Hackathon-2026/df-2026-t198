# しくみの映像：第2段階

初めて見る人が、締切変更が学生のLMS閲覧をきっかけに届くことと、面談で準備を決める流れを約30秒で追える映像を作る。根拠はIssue #262、PR #266のSoraの選択、および合意済みの映像要件。授業・人物・日付は架空。紹介ページの他章と学生・面談の製品画面、取得・API・保存処理は変更しない。

1. `story/people.tsx`・`props.tsx`・`catalog.tsx`・`page.tsx`・`scenes.tsx`・`screens.tsx`と色トークン：配色Bのみ残す。研究室のホワイトボード・資料棚・2台目のモニターを描く。相談室の時計を木枠・水色の液晶・7セグメントのSVGにし、机と道具の接地を確認する。不要な配色画像を除く。
2. `mechanism.tsx`・`mechanism.css`と`story/`内の映像部品：5場面・まとめ・ロゴ。場面内の経過時間から人物・吹き出し・時計の状態を決め、場面移動で残像や前の予定を引き継がない。時計へのズーム・時間送り・次の時計からの引きを描く。音はWeb Audioのみ。停止中・画面外・動きを減らす設定では動かさない。
3. 素材・紹介ページの単体試験、`landing-flow.browser.mjs`・`landing-chapters.browser.mjs`・素材ブラウザ試験を要件に合わせる。新しい場面は要件から直接検証する。既存の正解見本・指標の基準は変更しない。
4. 1280×720・紹介1280/390の全7場面、置時計の拡大、途中の画面書き換え・入室・一時停止・任意移動・キーボード・スワイプ・静止一覧を確認し、画像をこの記録ディレクトリに保存する。録画スクリプトはWeb Audioの出力も収録し、`out/issue-262/mechanism.mp4`を作る。音声トラック・長さ・無音でないことをffprobe/ffmpegで確認する。
5. 指定6検査、紹介ページブラウザ試験、QA・M6・public-demo、UTCの試験を実行する。エミュレーターは既存の利用者を止めず、ポートが空くまで待つ。C38は動画提出全体の条件なので、この部分映像だけではチェックしない。新たなC条件の達成がなければ進捗の数字を増やさない。

依存・API・データ形・実アカウント・デプロイの変更が必要になった場合は止まり、根拠と代案をIssueへ返す。レビュー用には変更・検証・未確認の範囲をPR #266にまとめる。mergeとデプロイは行わない。
