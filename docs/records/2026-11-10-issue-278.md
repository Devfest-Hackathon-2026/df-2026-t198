# Issue #278：学生画面からカレンダーとメールの設定を始める（2026-11-10）

## 変更と判断

- 学生画面の時間割の上に「Google カレンダーに予定を入れる」「朝のメールを受け取る」を置き、設定後は同じ場所に状態を出す。言葉は [ui-words.md](../ui-words.md#カレンダーとメールの入口issue-278)。
- 学生画面から拡張へ送れる命令は状態の確認・接続・同期の3つ。決定はD47、契約は [data-shapes.md](../data-shapes.md#学生画面から拡張への命令issue-278)。保存するデータの形、サーバーのAPI、Firestoreの規則、依存は変えていない。
- 依頼文のメールの節は「移行前の学生はクラウドで有効化できない」前提だったが、D46（Issue #274）で本人がクラウド送信へ切り替えられる。Soraの回答により、メールのボタンはD46の設定APIを呼ぶ。学生画面から拡張のGmail送信を始める経路は作っていない。依頼文の「移行前の利用者をクラウドで有効化できないこと」の確認は、D46と逆になるため行っていない。代わりに、有効化できない条件（体験用、宛先未確認、送信元の未準備）を確認した。

## 実際のGoogleアカウントで確認した結果

**未確認。** この作業では実際のGoogleアカウント、実物のカレンダー、本番の学生画面を使っていない。次は人の操作が要る。

1. 設定済みの拡張（`config.local.json` あり）をビルドして読み込み、本番と同じプロジェクトの学生画面を開く。本番の学生画面は今回の変更のデプロイ後でないとボタンが出ない。
2. 未接続のアカウントで「Google カレンダーに予定を入れる」を押し、Googleの確認画面を通る。Google カレンダーに「ToDoku」が1つでき、締切と保存済みの準備の予定が入ることを見る。
3. もう一度読み込み、状態が「連携済み」のままで、カレンダーと予定が増えていないことを見る。
4. 設定画面の接続テストで接続済みのアカウントでは、既存の「ToDoku・接続テスト」が使われ、新しいカレンダーができないことを見る。
5. 確認画面を閉じる（拒否）と案内が出て、同じボタンでやり直せることを見る。
6. 学生画面と違うGoogleアカウントのChromeプロファイルで押し、接続が止まって案内が出ることを見る。
7. Chromeを閉じた状態でスマホから準備の予定を保存し、スマホで「同期待ち」、PCのChromeで学生画面を開いたあと「連携済み」になることを見る。
8. 「朝のメールを受け取る」を押し、次の07:30に本人のアドレスへ届くことを見る（D46の実受信の確認と同じ）。

拡張を入れ直したあとにサーバーへ登録済みのカレンダーを読む `calendars.get` は、Googleの文書で `calendar.app.created` の権限で呼べることを確かめたが、実物では未確認。
