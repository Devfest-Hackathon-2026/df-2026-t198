# PR #116 の指摘1〜4の修正計画

目的は本人向けGmail通知の問い合わせ過多と、1件の失敗が後続通知や状態表示を壊す問題を修正し、Claudeが再確認できる試験を残すこと。依存・scope・共有型・APIは変更せず、実Gmail送信・Cloud設定変更・mergeは行わない。

- `packages/extension/src/digest-browser.ts` と `tests/digest-browser.test.mjs`：worker読込時は登録のみ。起動・インストール・アラーム・設定ONから処理する。日付・取得試行時刻・予定IDと開始時刻・問い合わせ済みIDだけを本人別に保存し、本文や課題名を保存しない。15分ごとの更新と未問い合わせの朝・予定の窓だけで取得する。失敗時も時刻を保存し、再開を繰り返した日の取得回数を数える。
- `src/calendar-browser.ts` と `tests/calendar-browser.test.mjs`：worker読込時の同期を起動・インストールへ移す。alarmでの再開は同期しないこと、従来の起動・観測後の同期を確認する。
- `src/digest.ts` と `tests/digest.test.ts`：#112のsafeTextと同じ資格情報名を拒否し、通常の課題名とURLの@を許す。既知の秘密値・符号化されたSID・宛先境界の試験は維持する。
- 1通ごとに失敗を分離し、朝や先頭予定が拒否されても正常な後続予定を送る。最後の非同期の本人・同意確認より後に送信記録を書き、期限切れ予定だけを飛ばす。保存中の期限切れやOFFは予約を戻す。
- 問題の表示は日付更新で消し、正常なempty・送信対象なしでも回復可能な表示を消す。同日の送信応答不明は未着の可能性が残るため維持する。

先に不具合の再現試験を追加し、意図した失敗を確認してから実装する。完了根拠は各試験と指定の6検査、`git diff --check`。PLANの既存C番号を新たに満たす変更ではないためチェックを増やさず、`pnpm progress --write` で整合を確認する。最後に同じissue-113へ通常pushし、PRの5見出しを保って最新の結果に更新、PRとIssueへ短く引き継ぐ。権限外の変更・契約変更が必要なら停止する。

## 検証結果

- 修正前のコードで、読み込み時の取得、1日分の取得増幅、メールの巻き添え停止、予約後の非同期確認、保存中のOFF・期限切れ、正常時と翌日の表示消去の失敗を再現した。予約の3試験は元のコードで3件失敗、修正後は成功。
- 1,440分すべてでworkerを読み直し、アラームと重複呼出しを与える試験：正常時は97回、APIが失敗し続ける場合は96回のdigest取得。更新は15分以上空け、未問い合わせの朝・予定の窓だけ追加で取得する。固定の予定集合に対する上限は96＋朝1＋予定ID数（同時刻の分はまとめる）。予定の取消も、窓で再取得した最新応答に従う。
- `pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm progress --check && pnpm check:samples`：すべて終了コード0。core 167件、extension 210件、server 151件、web 50件成功。通常実行でserver 38件・web 2件はskip。別枠でHosting 8件、Firestore規則38件がエミュレーターで成功。見本17ファイル成功（手元の実物との比較は資料なしのためskip）。
- `pnpm progress --write`：全体31/43・必須29/39。新たに満たすC番号はなく、mainの数字を維持。M1〜M7の測定条件・見本の正解は変更しない。
- #112のsafeTextを基準として、単独のtoken・session・auth・password等の語だけで秘密と判定する旧試験を外し、通常のToken:・Secret=・URLのパスの@を許す試験を追加。SID・Cookie・Authorization・資格情報付きURL・既知の秘密値・エンコードの拒否は維持する。任意の未知の秘密を識別できる保証はない。
- 同日の送信応答不明は、届いたか判断できないため表示を維持する。翌日には消す。回復可能な問題は正常なempty・対象なしでも消す。送信予約とHTTP送信は原子的にはできず、予約直後のworker停止による未着の可能性は残る。

変更した権限境界は、本人へのGmail送信前の同意・本人確認と本文検査。偽APIと架空の値だけで確認し、保存対象に本文・メールアドレス・トークンがないことも試験した。依存・DB規則・課金・本番設定は対象外。実Gmail受信、#112の公開APIとの通し、OAuth同意画面へのscope追加は、従来どおりmerge後のSoraの確認に残る。
